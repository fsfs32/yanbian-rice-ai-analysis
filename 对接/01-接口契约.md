# 前后端接口契约（唯一接口）

> 本文档是前端与后端的**唯一契约**。前端所有请求都发往同一个接口，后端必须严格按本文返回，否则前端运行时校验会直接判定「数据格式异常」并降级。

---

## 1. 接口总览

| 项 | 值 |
|---|---|
| 方法 | `POST` |
| 路径 | `/api/ask` |
| 请求头 | `Content-Type: application/json`<br>`Accept: text/event-stream, application/json` |
| 前端超时 | 15 秒 |
| 响应方式 | 普通 JSON 或 SSE（`text/event-stream`），**二选一** |

前端默认请求地址：`http://127.0.0.1:8000`（由前端环境变量 `VITE_API_BASE_URL` 指定）。

---

## 2. 请求体（前端 → 后端）

```json
{
  "question": "延边 2001 年产量怎么样？",
  "history": [
    { "role": "user", "content": "上一句问题" },
    { "role": "assistant", "content": "上一句回答" }
  ],
  "session_id": "uuid-xxxx",
  "csv": {
    "file_name": "长势与销售额.csv",
    "headers": ["年份", "产量(吨)", "销售额(亿元)"],
    "rows": [
      ["2020", "190000", "9.5"],
      ["2021", "196000", "9.8"]
    ]
  }
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | ✅ | 用户输入的问题 |
| `history` | array | 否 | 多轮上下文，用于指代消解，元素形如 `{role, content}` |
| `session_id` | string | 否 | 会话标识 |
| `csv` | object | 否 | **存在即代表"文件分析"场景**，后端据此走文件分析分支 |

`csv` 子字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `file_name` | string | 文件名 |
| `headers` | string[] | 表头 |
| `rows` | string[][] | 数据行（前端已解析为字符串二维数组） |

> **关键**：前端通过「请求体是否带 `csv` 字段」区分两种场景，后端据此分流：
> - 带 `csv` → 分析上传数据
> - 不带 `csv` → 普通问答

---

## 3. 响应体（后端 → 前端）：`AskResponse`

```json
{
  "chart_config": {
    "chart_type": "combo",
    "x_field": "year",
    "y_field": "yield",
    "y2_field": "revenue",
    "title": "1994—2016 年水稻产量趋势"
  },
  "labels": [1994, 1995, 1996],
  "values": [172000, 178000, 185000],
  "values2": [8.6, 8.9, 9.2],
  "summary": "从 1994 年到 2016 年，产量整体呈稳步上升趋势。",
  "source": "延边州统计局 · 1994—2016"
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `chart_config` | object | ✅ | 图表配置 |
| `labels` | array | ✅ | X 轴数据，元素为 `string` 或 `number` |
| `values` | number[] | ✅ | Y 轴数据，**必须为有限数字** |
| `values2` | number[] | 否 | 组合图第二序列（如销售额），**若存在必须与 `values` 等长** |
| `summary` | string | ✅ | 文字结论 |
| `source` | string | 否 | 数据来源，展示在图表底部 |

### 3.1 chart_config 字段

| 字段 | 类型 | 必填 | 取值 |
|---|---|---|---|
| `chart_type` | string | ✅ | `line` / `bar` / `scatter` / `combo` |
| `x_field` | string | ✅ | `year` / `yield` / `revenue` |
| `y_field` | string | ✅ | `year` / `yield` / `revenue` |
| `y2_field` | string | 否 | `year` / `yield` / `revenue`（仅 `combo` 时使用） |
| `title` | string | ✅ | 图表标题 |

---

## 4. 字段白名单（硬约束，务必遵守）

前端运行时校验（`src/utils/validateAskResponse.ts`）对以下取值做了严格白名单，**超出即报错**：

```text
chart_type ∈ { line, bar, scatter, combo }
x_field    ∈ { year, yield, revenue }
y_field    ∈ { year, yield, revenue }
y2_field   ∈ { year, yield, revenue }（可选）
```

其它硬校验：

- `labels.length === values.length`
- `values` 每个元素必须为 `typeof number` 且 `Number.isFinite`
- `values2` 若存在，必须 `length === values.length` 且元素为有限数字
- `summary` 必填且为 string（前端截断到 300 字符）
- `title` 为 string（前端截断到 80 字符）

> ⚠️ **如要新增维度字段**（例如「长势指数 growth」），必须同步改前端两处白名单：
> `src/types/index.ts` 的 `Field` 类型，以及 `src/utils/validateAskResponse.ts` 的 `FIELDS` 数组。

## 5. 纯文字回答（无图表场景）

当用户问「怎么提高产量」这类无法/无需画图的问题时，返回：

```json
{
  "chart_config": {
    "chart_type": "line",
    "x_field": "year",
    "y_field": "yield",
    "title": "分析"
  },
  "labels": [],
  "values": [],
  "summary": "提高水稻产量的关键措施包括……",
  "source": "AI 分析"
}
```

要点：
- `labels` 和 `values` 返回**空数组**（`[]`），前端会据此只渲染文字、不画图。
- `chart_config` 仍需提供（占位即可），因为它是前端校验的必填项。

---

## 6. 响应方式二选一

### 6.1 普通 JSON（简单）

`Content-Type: application/json`，直接返回 `AskResponse`。前端 `askQuestion()` / `streamQuestion()` 都能处理。

### 6.2 SSE 流式（推荐，体验更好）

`Content-Type: text/event-stream`，逐条发送 `data:` 事件：

```
data: {"delta":"从 1994 年到 2016 年，"}

data: {"delta":"产量整体呈稳步上升趋势。"}

data: {"chart_config":{"chart_type":"combo","x_field":"year","y_field":"yield","y2_field":"revenue","title":"1994—2016 年水稻产量趋势"},"labels":[1994,1995],"values":[172000,178000],"values2":[8.6,8.9],"summary":"从 1994 年到 2016 年，产量整体呈稳步上升趋势。","source":"延边州统计局 · 1994—2016"}

data: [DONE]
```

前端解析规则（`src/api/askApi.ts`）：

- 每行以 `data:` 开头，`data:` 后为 JSON。
- 载荷含 `delta` 字段 → 作为**增量文本**逐字渲染。
- 载荷含 `summary` 且 `chart_config` → 作为**最终完整载荷**（`AskResponse`）。
- `data: [DONE]` → 表示流结束。
- 无法解析的分片会被前端忽略。

> 建议：先发若干 `delta` 增量，最后发一条完整 `AskResponse`，再发 `[DONE]`。

## 7. AI 深度要求（不踩红线）

前端只做展示，**AI 能力全在后端**。评审要求「深度集成，而非简单 API 调用」，后端必须做到：

1. **System Prompt 立人设**：明确"你是延边大米数据分析专家，只能基于真实数据回答，禁止编造数字"。
2. **Function Calling / JSON Mode 结构化输出**：强制 LLM 返回 `AskResponse` 结构，而非自由文本。
3. **数据来自工具/真实数据源**：产量等数字通过工具调用从数据源查询，而非让 LLM 编造。
4. **返回前校验 + 失败兜底**：后端自校验格式，失败重试或返回降级提示。

> 骨架代码 `backend/app/services/` 已按此设计实现，直接改造即可。

## 8. CORS 要求

后端需允许前端来源跨域访问，开发环境至少放行：

```
http://localhost:5173
http://127.0.0.1:5173
```

骨架已内置 CORS 中间件。

## 9. 联调自检清单

按序验证，全部通过即视为「接通跑通」：

1. ✅ `POST /api/ask` 返回 `200`，`Content-Type` 为 `application/json` 或 `text/event-stream`。
2. ✅ 返回体含 `chart_config` + `labels` + `values` + `summary`，且 `labels.length === values.length`。
3. ✅ `chart_type` / `x_field` / `y_field` 取值在白名单内。
4. ✅ 前端界面提问后，**右下角不出现「演示数据」标签**（出现即说明请求失败走了降级）。
5. ✅ 前端能看到「AI 分析流程」五步状态条推进。
6. ✅ 上传 CSV 后，后端能收到 `csv` 字段并返回分析结果。
7. ✅ 问「怎么提高产量」这类问题，返回 `labels:[]` 且前端只显示文字、不出图。
