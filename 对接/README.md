# 前后端对接交接包

> 本目录用于**后端工程师**接手前端项目，按约定实现后端服务并完成联调。
> 后端工程师只需阅读本目录，无需理解前端全部源码即可开工。

---

## 一、你需要交付什么

实现一个 **Python FastAPI 后端服务**，对外暴露 **1 个 HTTP 接口**，配合前端完成「AI 数据分析与可视化」能力。

**核心结论先行：前端只依赖一个接口，不要多写、也不要少写。**

| 项 | 内容 |
|---|---|
| 接口数量 | **1 个**：`POST /api/ask` |
| 承载能力 | 普通问答、CSV 文件分析、纯文字回答、流式输出 |
| 返回格式 | 标准 `AskResponse`（见 `01-接口契约.md`） |
| AI 要求 | 深度集成，**禁止裸调大模型**（详见契约文档） |

## 三、开工步骤（建议顺序）

1. 通读 `01-接口契约.md`，**重点看「字段白名单」和「SSE 格式」**——这是前端校验的硬约束，不满足前端会直接显示"数据格式异常"。
2. 打开 `backend/`，把骨架跑起来（见 `backend/README.md`）。
3. 填入你的大模型 API Key，替换骨架里的 TODO，实现真正的 AI 分析。
4. 按契约文档末尾的「联调自检清单」逐项验证。

---

## 四、三条红线（务必遵守）

1. **不得裸调大模型**：不能 `llm.chat(question)` 直接返回自由文本，必须用 `System Prompt + Function Calling/JSON Mode + 结构化输出`（详见契约文档 §AI 深度要求）。
2. **返回格式必须过白名单**：`chart_type`、`x_field`、`y_field` 的取值是固定枚举，错一个前端就报错。
3. **API Key 不得硬编码**：只能通过环境变量注入。

详细说明见 `01-接口契约.md`。
